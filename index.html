Security posture & enterprise deploymentLocal demo controls · production gates

Active in this demo

  • Local processing: imported scenario data remains in browser memory; this browser demo has no account, telemetry, or network integration.
  • Slurm advisory: a separate local CLI can read an authorized Slurm snapshot and emit recommendations without changing scheduler state. It needs real due times and site signals. Open the integration guide.
  • Content Security Policy: network connections and unapproved scripts are blocked; the app script is allowlisted by hash.
  • Input limits: JSON files are capped at 256 KB and checked against a fixed schema, numeric ranges, time steps, job count, and safe job IDs.
  • No persistence: uploaded data is not written to local storage or sent to a service.
  • Slurm output handling: advisory files are owner-only where supported; existing outputs, symbolic-link destinations, and input/output collisions are rejected unless replacement is explicitly requested.

Required before a company pilot

  • Company SSO, role-based permissions, tenant isolation, and least-privilege service identities.
  • Approved hosting, encrypted transport and storage, audit trails, retention rules, and incident response ownership.
  • Security threat modeling, dependency and deployment controls, and review by the company’s security team.
  • Read-only integration first; operational control requires validated site data, engineering sign-off, and a human-approved fail-safe path.
Model note: illustrative 15-minute traces and a multi-start local-search heuristic. Cost and emissions use synthetic hourly profiles. The demo does not model electrical frequency response, GPU hardware behavior, or utility protection systems. It is independent of Google, NVIDIA, and Microsoft; none has evaluated or endorsed it. It is a local prototype, not a production enterprise service or operational control system.
